# Academy security policies V1

## `PASSWORD_POLICY_V1`

- Argon2id credential hashing (`ARGON2ID_V1`).
- 12–256 Unicode characters; long passphrases are accepted.
- No plaintext, reversible password, hint, or password-derived audit metadata.

## `SESSION_POLICY_V1`

- 32 random bytes encoded base64url; SHA-256 digest only in PostgreSQL.
- Seven-day absolute expiry.
- Development cookie: `chess_session`.
- Production cookie: `__Host-chess_session; Secure; HttpOnly; SameSite=Lax; Path=/`.
- Logout, revoke-all, and password-change revocation are server-side.

## `AUTH_RATE_LIMIT_V1`

- Five failed attempts per normalized-email digest in a rolling 15-minute window.
- Unknown accounts execute a constant dummy Argon2 verification path.
- Public response does not distinguish an unknown email from a wrong password.

## `ACADEMY_INVITATION_POLICY_V1`

- Invitation-only registration and seven-day expiry.
- Raw token is delivered once through the configured provider and never persisted or returned by production APIs.
- Owner/Admin may create and revoke; only Owner may invite Owner.
- Student invitations must claim the existing membership linked to the StudentProfile.
- Normalized email must match. Acceptance is one transaction and cannot be reused.

## `PASSWORD_RESET_POLICY_V1`

- 32 random bytes encoded base64url; SHA-256 digest only in PostgreSQL.
- One-hour absolute expiry and single-use atomic consumption.
- At most three request observations per normalized-identifier digest in a rolling hour.
- Request response is identical for known, unknown, and throttled identifiers.
- Successful completion replaces the Argon2id credential and revokes every active session and other unused reset token in the same transaction.
- Delivery state and audit provenance contain no raw token. SMTP errors are not exposed through the public enumeration-resistant endpoint.

## Email delivery V1

- `EmailDeliveryProvider` keeps invitation/reset logic vendor-neutral; V1 supplies SMTP and disabled adapters.
- Production requires explicit SMTP, sender, public HTTPS base URL, and exact allowed origins.
- Mailpit is acceptance infrastructure only, never a production provider.
- Possession of a delivered link proves link possession, not verified real-world identity.

## `ACADEMY_RBAC_V1`

| Capability                                 | Owner | Admin | Coach | Student |
| ------------------------------------------ | ----: | ----: | ----: | ------: |
| Academy manage                             |   yes |    no |    no |      no |
| Membership/invitation/consent/audit manage |   yes |   yes |    no |      no |
| Roster and Student Intelligence read       |   yes |   yes |   yes |      no |
| Assignment read/write                      |   yes |   yes |   yes |      no |
| Student self read and training submit      |  yes* |    no |    no |     yes |

`*` Owner has the capability in the complete matrix, but Student endpoints additionally require a real STUDENT membership and StudentProfile; role capability alone cannot impersonate a Student.

The last Owner is protected. Admin cannot promote to or manage an Owner. Membership disable is Academy-local.

## `CSRF_ORIGIN_POLICY_V1`

Safe methods are GET, HEAD, and OPTIONS. Cookie-authenticated mutations require an exact configured Origin. Non-browser clients without a session cookie may omit Origin, but still require authentication where the route requires it. CORS permits the configured web origin with credentials.

## Student consent access

- `NOT_REQUIRED` and `GRANTED`: Student self-service and assigned scored attempts allowed.
- `PENDING` and `REVOKED`: Student authentication may succeed, but self-service and new scored attempts return `GUARDIAN_CONSENT_REQUIRED`.
- Only Owner/Admin can set the requirement or append the Academy-recorded status.
- Existing evidence is retained after revocation.

These values describe product state. They do not assert legal compliance or verified guardian identity.

## Operational HTTP boundary

- `/livez` proves only that the API process can answer.
- `/readyz` requires PostgreSQL connectivity and migration `014_production_verification_foundation.sql`; it fails with 503 when those dependencies are unavailable or stale.
- Every response carries an `x-request-id` plus nosniff, no-referrer, frame-denial, and `frame-ancestors 'none'` headers.
- Structured request logging redacts credentials, cookies, response cookies, password fields, raw-token fields, and invitation bearer URL segments.
