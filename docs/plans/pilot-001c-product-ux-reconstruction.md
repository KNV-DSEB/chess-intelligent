# Pilot 001C — Product UX Reconstruction & Pilot Experience V2

## Scope

Reconstruct the existing Web presentation and navigation around the verified learning loop without
changing chess truth, analytical policy, Academy authorization, persistence, or Pilot event
semantics. The work consumes only existing production API contracts. Acceptance fixtures are
development-only and never count as deployed Pilot evidence.

## Direction contract

**THESIS:** A coach should read one unfolding evidence-to-practice story, not operate an internal
artifact dashboard. Refuse the equal-weight card grid.

**OWN-WORLD:** A master-game folio: warm paper, forest authority rails, amber pencil annotations,
compact score-sheet rows, quiet rules, and restrained state color.

**STORY:** See who needs attention, understand why, inspect the decisive position, assign verified
practice, then review new evidence.

**FIRST VIEWPORT:** Role-aware rail and compact academy header frame a priority ledger; one student
decision row leads directly to evidence and a next action.

**FORM:** Operate surface, grounded direction 7, seed `1d855d4f`; the brief-pinned incumbent world
overrides catalog challengers. Signature interaction: priority row → chess position evidence →
training action without losing context.

**FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review, the
verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Delivery boundary

- Role-aware information architecture for Coach and Student.
- Coach Home, roster, Student Intelligence, Skill Map, evidence, assignment, and progress redesign.
- Student Today, assignment, training item, and progress redesign.
- Optional AI remains subordinate and absent from primary navigation.
- No new chart library, API route, database migration, classifier, training policy, ontology change,
  or product capability.

## Acceptance

Use deterministic Academy fixture data to exercise the real HTTP/application/repository boundary.
Verify desktop, tablet, and mobile layouts; keyboard flow; error/empty/readiness states; role and
tenant denials; Pilot event deduplication; answer privacy; and existing API response compatibility.
