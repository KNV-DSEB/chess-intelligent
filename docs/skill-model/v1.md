# Skill Graph policy V1

This document is the reproducible specification for `SKILL_GRAPH_POLICY_V1`. The implementation constants and deterministic policy hash live in `packages/domain/src/player-skill-graph.ts`.

## Pinned inputs

One run identifies:

- focal Player;
- explicit published `ontologyVersion`;
- `CONCEPT_CLASSIFIER_BUNDLE_V1` and its exact configuration SHA-256;
- `CLASSIFICATION_SELECTION_V1`;
- normalized evidence scope;
- explicit date-only `asOfDate`;
- selected input snapshot SHA-256.

No ontology version mixing or implicit `latest` selection is permitted.

## Classification selection

For every selected canonical Game:

1. retain only `SUCCEEDED` runs with the exact ontology version, classifier bundle, and classifier configuration hash;
2. a non-null selected analysis run must be a successful `QUICK_V1`, profile-version-1 run;
3. prefer engine-backed compatible runs over no-engine compatible runs;
4. within that class, order by completion time descending and immutable run ID descending;
5. choose at most one run.

Multiple immutable reruns of one Game are not independent evidence samples.

## Coverage

- `canonicalGames`: distinct focal-player Games matching scope.
- `gamesWithMoves`: selected Games with canonical moves.
- `decisionOccurrences`: distinct occurrences where the focal player's color is side to move.
- `classifiedDecisions`: distinct focal decisions with one or more selected-run focal-player `DECISION` evidence rows.
- `engineBackedDecisions`: distinct focal decisions with a state in the selected run's compatible analysis run.
- `masteryEligibleEvidence`: exact focal-player `DECISION`, `POSITIVE`/`NEGATIVE`, engine-provenanced evidence rows whose role weight is greater than zero.

Absent classification or engine rows remain unknown and add no negative evidence.

## Eligibility and role weights

Historical role comes from the immutable Task 008 evidence instance.

```text
DIRECT      1.00
SUPPORTING  0.50
CONTEXTUAL  0.00
```

`NEUTRAL` and `POSITION` evidence always add zero mastery mass. Contextual and neutral observations remain available as counts/drill-down context.

## Game correlation cap

For one Player, concept, and canonical Game, let raw weighted evidence be:

```text
P = sum(weight(e)) for POSITIVE evidence
N = sum(weight(e)) for NEGATIVE evidence
T = P + N
scale = min(1, 1 / T), for T > 0
cappedPositive = P × scale
cappedNegative = N × scale
```

The maximum pre-recency Game contribution is `1.0`. Evidence below the cap is not inflated. Positive/negative proportions are preserved.

## Date and recency

The evidence date is canonical `games.played_at`; if absent, the Task 008 evidence creation date is used. Dates use calendar-date arithmetic through UTC epoch days, avoiding local-midnight PostgreSQL `DATE` conversion. Future-dated evidence relative to the recency anchor is assigned age zero.

```text
ageDays = max(0, asOfDate − evidenceDate)
recencyWeight = 0.5 ^ (ageDays / 365)
effectivePositive = cappedPositive × recencyWeight
effectiveNegative = cappedNegative × recencyWeight
```

Old evidence decays but does not disappear.

## Beta posterior heuristic

The V1 prior is `Beta(2, 2)`:

```text
positiveMass = sum(effectivePositive)
negativeMass = sum(effectiveNegative)
alpha = 2 + positiveMass
beta = 2 + negativeMass
posteriorMean = alpha / (alpha + beta)
effectiveEvidenceMass = positiveMass + negativeMass
```

This is Bayesian-style evidence aggregation, not Bayesian Knowledge Tracing. There are no learning transitions, guess/slip probabilities, or sequential latent states.

## Evidence confidence

Confidence describes evidence support, not the player's psychological confidence:

```text
INSUFFICIENT  effective mass < 1.5 OR canonical mastery Games < 2
LOW           1.5 <= effective mass < 4
MODERATE      4 <= effective mass < 8
HIGH          effective mass >= 8
```

`INSUFFICIENT` forces `INSUFFICIENT_EVIDENCE`. A high posterior based on one Game cannot receive ordinary confidence or a mastery band.

## Mastery bands

Bands apply only to `ESTIMATED` states:

```text
EMERGING                     posterior < 0.40
DEVELOPING                   0.40 <= posterior < 0.65
ESTABLISHED                  0.65 <= posterior < 0.85
STRONG_EVIDENCE_OF_MASTERY   posterior >= 0.85
```

`NO_EVIDENCE` exposes no mastery percentage; a Beta prior mean of 0.5 is not player evidence. `INSUFFICIENT_EVIDENCE` retains posterior inputs for reproducibility but the ordinary graph UI hides its percentage.

These bands are descriptive evidence states. They are not weakness, strength, training-priority, or recommendation labels.
